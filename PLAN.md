# Пошаговый план работ

План рассчитан на один проект «под ключ»: старый Samsung Tizen TV → аккуратный минималистичный
лаунчер. Каждая фаза заканчивается **проверяемым результатом** (файл/лог/фото), иначе не идём дальше.
Ориентировочно: 2–4 вечера для опытного исполнителя, больше — если идти с нуля по этому плану.

> Правила: ничего не удалять без согласия владельца; перед изменениями — бэкап; каждый шаг
> должен иметь путь отката. Если факт нельзя проверить — считаем его неизвестным, а не «наверное, работает».

---

## Фаза 0. Подготовка (0.5–1 ч)

**Цель:** рабочее место и правила игры.

- [ ] Рабочая папка проекта (`toolchain/`, `launcher/`, `scripts/`, `backup/`, `tv/`, `docs/`).
- [ ] Mac (или Linux) в той же сети, что ТВ; TV в сети по кабелю — стабильнее.
- [ ] На Mac: `sdb`, Tizen CLI, сертификат Samsung Public (Apps2Samsung CLI), Python-зависимости.
- [ ] Создан `backup/<timestamp>/`, в нём `CHANGES.md` с шаблоном «что/где/было→стало/откат».
- [ ] Прочитан `docs/settings-before.md`: какие настройки придётся менять и как возвращать.
- [ ] Согласовано с владельцем: какие приложения и функции нужны, что можно трогать.

**Готово, если:** есть папка проекта, инструменты установлены, владелец подтвердил границы.

---

## Фаза 1. Разведка ТВ (0.5–1 ч)

**Цель:** точный «паспорт» устройства, без которого дальше нельзя.

- [ ] Найти ТВ в подсети: ARP/скан портов `8001` (REST), `8002` (websocket), `26101` (SDB).
- [ ] Снять `GET http://<IP>:8001/api/v2/` → `backup/<ts>/api_v2.json`.
- [ ] Зафиксировать: модель, `firmwareVersion`, платформу (Tizen-версия, SoC), DUID, `developerMode`.
- [ ] Определить входы/источники (HDMI) и нужные владельцу приложения.
- [ ] Сфотографировать главный экран и меню настроек «до» (телефоном).

**Готово, если:** в `api_v2.json` и заметках есть модель, платформа, DUID; фото «до» сохранены.

---

## Фаза 2. Режим разработчика и SDB (0.5–1 ч)

**Цель:** командный канал до ТВ.

- [ ] Открыть `Apps → 12345` и пройти диалог: `Вкл.`, IP Mac по октетам (`KEY_RIGHT` между октетами!), `OK`.
- [ ] Перезагрузить ТВ; проверить по REST `developerMode: 1`, `developerIP: <Mac>`.
- [ ] `sdb connect <IP>:26101`; `sdb shell 0 applist` возвращает список приложений.
- [ ] Проверить websocket-пульт (`wss://<IP>:8002`) — понадобится для автоматизации тестов.

**Готово, если:** `applist` отвечает, пульт по сети работает (нажатия доходят).

---

## Фаза 3. Проверка root и границ платформы (1–2 ч)

**Цель:** не потратить недели на невозможное.

- [ ] Проверить браузер ТВ: UA, `typeof WebAssembly` (для старых Tizen — отсутствует).
- [ ] Проверить `sdb capability`: `secure_protocol`, `rootonoff_support`, `filesync_support`.
- [ ] Проверить, какие shell-команды реально разрешены (`applist`, `was_execute`, `vd_appinstall`…).
- [ ] Сверить модель/прошивку с известными root-методами (SamyGO K-root, USB-методы).
- [ ] Проверить инъекции через SDB (`;`, `$()`, backtick) — на Tizen 2.4 не исполняются.
- [ ] Записать выводы в `docs/root-assessment.md` с доказательствами.

**Готово, если:** решение «root да/нет» обосновано фактами. Если нет — фиксируем маршрут
«штатные настройки + свой web-лаунчер» и не возвращаемся к root без новых данных.

---

## Фаза 4. Бэкап и обратимость (0.5 ч)

**Цель:** в любой момент вернуть всё назад.

- [ ] `scripts/backup.sh` → `api_v2.json`, `applist`, попытки `vconf`, фото настроек.
- [ ] Записать текущие значения всех переключателей, которые планируется менять.
- [ ] Написать/проверить `scripts/restore.sh` (хотя бы: вернуть настройки, переустановить штатный лаунчер).
- [ ] Проверить, что restore запускается и не требует ручных тайн.

**Готово, если:** бэкап лежит в `backup/<ts>/`, restore протестирован «на сухую».

---

## Фаза 5. Реклама и телеметрия без удаления (0.5–1 ч)

**Цель:** меньше рекламы и слежки, ничего не ломая.

- [ ] Настройки → Параметры конфиденциальности → снять Interest Based Advertisement и ACR
      (Viewing Information Services), голосовые — отключить.
- [ ] Online Remote Management → Выкл.
- [ ] Обновление ПО → Автообновление → Выкл.
- [ ] Спросить владельца: автостарт Smart Hub, Samsung Instant ON.
- [ ] Подготовить DNS-блоклист для роутера (реклама в Smart Hub настройками не выключается).
- [ ] **Не удалять** предустановленные приложения: на retail нельзя (ошибка 132).
- [ ] Каждое изменение — строка в `CHANGES.md`, фото экрана после.

**Готово, если:** переключатели выключены и сфотографированы, блоклист сохранён, ничего не удалено.

---

## Фаза 6. Своё приложение: сборка, подпись, установка (2–4 ч)

**Цель:** научиться ставить и запускать свой web-app на ТВ.

- [ ] Сертификат Samsung Public, привязанный к DUID (`apps2samsung-cli cert --prepare …`).
- [ ] Tizen CLI профиль (`samsung`), патч сигнера на SHA-256 для Tizen 2.4.
- [ ] Минимальный `config.xml`: package id **ровно 10 символов**, `required_version=2.3`,
      `tizen:profile tv-samsung`, привилегии `internet`/`application.launch`.
- [ ] Сборка `tizen package -t wgt -s samsung -o <абс. путь> -- <app>`.
- [ ] Установка: `sdb push` → `sdb shell 0 vd_appinstall <package> <path>` → `was_execute <appId>`.
- [ ] Разобраться с ошибками: `[118]` (сертификат/длина id/подпись), `[16]` (неверный путь wgt).

**Готово, если:** тестовое приложение установилось и запускается, в `applist` появилось его id.

---

## Фаза 7. Лаунчер: экран, док, обои (1–2 дня)

**Цель:** свой главный экран, удобный обычным пультом.

- [ ] Каркас: часы, док избранных, сетка «Все приложения», навигация ← → ↑ ↓ OK Back.
- [ ] Конфиг **встроить в JS** (`config.js`): XHR на `file://` в WebKit 2.4 заблокирован.
- [ ] Обои: 4–6 картинок 960×540 (быстрый декод), смена по таймеру, два слоя для перекрёстного затухания.
- [ ] Иконки 176 px, в сетке — ленивая загрузка.
- [ ] Запуск приложений по плитке; HDMI — через `tizen.tvwindow`.
- [ ] Зафиксировать поведение в `docs/launcher-spec.md` (инварианты + приёмочные тесты).

**Готово, если:** тесты по спецификации проходят на ТВ, навигация не «залипает».

---

## Фаза 8. Скорость и возврат из приложений (0.5–1 день)

**Цель:** «нажал — открылось», «вышел — вернулся».

- [ ] Измерить: возврат из лёгкого приложения должен быть мгновенным (только repaint, без декода).
- [ ] Проверить, какие плееры вытесняют лаунчер из памяти (у нас — Wink).
- [ ] Опционально: пометить тяжёлый плеер `"heavy": true` → лаунчер после запуска вызывает
      `tizen.application.getCurrentApplication().exit()` и отдаёт память. Плата: после выхода
      из такого плеера возврат вручную — Home → Smart Hub → APPS → AiTV.
- [ ] Проверить по камере: старт тяжёлого плеера ускорился; возврат по Back и через Smart Hub работает.

**Готово, если:** старт тяжёлого плеера стал быстрее и понятно, как вернуться в любом режиме.

---

## Фаза 9. Визуальная самопроверка (0.5 дня)

**Цель:** больше не спрашивать владельца «работает?» — проверять самому.

- [ ] Камера (Mac-приложение на AVFoundation или `tv/snap.py`) пишет кадр раз в 1–2 с.
- [ ] `tv_remote.py` шлёт клавиши по websocket.
- [ ] Пройти приёмочные сценарии, сохраняя кадры: запуск приложения, возврат, Home, HDMI.
- [ ] Кадры-доказательства — в `backup/photos/` с подписями.
- [ ] Сравнить факты со спецификацией; расхождения — в отчёт, не «замазывать».

**Готово, если:** по каждому пункту приёмки есть кадр, и они совпадают с ожиданием.

---

## Фаза 10. Сдача (0.5 дня)

**Цель:** владелец понимает, что сделано и как откатить.

- [ ] `README.md`: статус, что установлено, ограничения, как удалить/вернуть.
- [ ] `docs/final-report.md`: что/как/чем подтверждено + таблица ловушек платформы.
- [ ] `docs/settings-before.md`: таблица изменённых настроек и откат.
- [ ] `scripts/restore.sh` и `scripts/snapshot.sh` работают.
- [ ] Владелец проинформирован: что не будет работать (root/Home/системные приложения) и почему.

**Готово, если:** по документам новый человек/ИИ может повторить проект и откатить всё.

## Приложение: что считается «проверкой»

| Тип проверки | Пример |
|---|---|
| Факт с устройства | `GET /api/v2/`, `sdb shell 0 applist`, `capability` |
| Визуальный факт | фото/кадр камеры экрана ТВ в конкретной фазе сценария |
| Лог программы | вывод `tizen package`, `vd_appinstall`, `sdb applist` |
| Поведенческий тест | нажали клавишу → ожидаемое состояние экрана в кадре |
| Обратимость | restore/переключатель вернул исходное состояние |

Если проверку сделать нельзя — пишем «не проверено», а не выдаём за факт.
